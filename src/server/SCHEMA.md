The MVP reads an in-memory, synthetic Aluva / Periyar graph. No Supabase account or secrets are required. API clients cannot persist reports or change the shared graph; closures are supplied per analysis request.

The draft migration defines future reports and enables RLS with no policies, revoking all anon/authenticated access. It has not been applied. A later release needs authenticated report submission, human verification, source timestamps, location/road linkage, abuse limits, audit history and expiry before any report can alter operational routing. Never treat user reports as verified closures automatically.

Graph edges are undirected, weights are positive illustrative kilometres, and coordinates use latitude then longitude. Route selection uses Dijkstra. Reachability is computed relative to the chosen origin; isolated settlements means settlements unreachable from that origin. Components count all nodes, including isolated facilities. None of the demo road geometries or facilities are real-world verified, and no flood-depth or vehicle-passability model is included.

`DemoProvider` validates the complete graph before serving either API. It rejects duplicate identifiers, missing road endpoints, parallel/self-loop roads, invalid latitude/longitude, geometry endpoint mismatches, negative/nonfinite weights and missing/malformed ISO timestamps. Zero weights are accepted by the schema and Dijkstra, though current fixtures use positive illustrative kilometres. Dataset size is bounded. The provider returns a newly parsed snapshot, and failures return a sanitized 503; no unvalidated fallback is substituted.

`getFreshnessMetadata` reports recent, stale, missing, invalid or future timestamps. The oldest generation/observation timestamp determines age; a one-hour default threshold is a demonstration policy only. Recent timestamps never mean verified observations or safe travel. The network response exposes mode/freshness headers while preserving its JSON contract. No timestamps are refreshed automatically.

Export a validated credential-free sample with `npm run import:demo -- --export docs/demo-network.json`. Validate/import a local JSON file with `npm run import:demo -- docs/demo-network.json data/demo-network.json`. Files are created exclusively, so choose a new output name when a file exists. Outputs must be JSON within the current workspace. The importer does not contact any database or change the running fixture. To intentionally replace the demo scenario, review the exported data and update `src/lib/fixtures.ts`, then run tests and production build.

Future real-data procedure: preserve authoritative attribution and original observation times; validate topology and coordinates against a licensed road source; separately verify every facility/access road and closure report; review publication rights and report moderation; define expiry and failure handling; introduce a separate provider contract with explicit verified/unverified states. Do not relabel this demo provider or rewrite timestamps to imply current conditions. A future Supabase connection requires credentials in local environment configuration, controlled migrations and server-only access; none is connected here.
